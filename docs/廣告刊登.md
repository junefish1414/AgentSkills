# 廣告刊登

> 本文件為團隊內部黑話字典條目，主要供 AI 理解 104 招募管理系統（B 端 / 求才端）的核心商業概念與術語慣例。

---

## 廣告刊登（簡稱：廣告）

**所屬端**：B 端（求才端 / 企業招募管理系統）

**定義**：104 提供給企業客戶的徵才服務本身。客戶購買廣告刊登後，於「廣告刊登中」期間，公司資訊與該公司**設定為開啟的職缺**會在 C 端（求職端）對外曝光。

**重要慣例**：

- 在 B 端系統中提到「廣告」，預設指的就是「廣告刊登」這個徵才服務，**不是**行銷廣告（如 Google Ads）。
- 「廣告刊登」≠ 單一職缺。一份 PO 單期間內，客戶可刊登多個職缺（數量依合約而定）。
- **C 端是否曝光，需同時滿足兩個條件**：公司狀態為 on 公司、且該職缺為 on 職缺。
- 「廣告刊登狀態 ON / OFF」即指公司狀態的 on 公司 / off 公司（見下方公司狀態表）。

**公司狀態**：

| 狀態名稱   | 內部黑話 | 說明                              |
| ---------- | -------- | --------------------------------- |
| 廣告刊登中 | on 公司  | 公司在 C 端曝光中（實際曝光的職缺，仍需該職缺為 on 職缺） |
| 暫停徵才中 | off 公司 | 公司在 C 端不曝光，但合約仍在     |

**職缺狀態**：

| 狀態名稱 | 內部黑話 | 說明                                              |
| -------- | -------- | ------------------------------------------------- |
| 開啟職缺 | on 職缺  | 該職缺被客戶設定為要對外曝光（仍需公司為 on 公司才會真正曝光） |
| 關閉職缺 | off 職缺 | 該職缺不對外曝光                                  |

**公司狀態與職缺狀態的關聯規則**：

- **off 公司 一定不會有 on 職缺**。只要公司狀態變為 off，系統會將該公司底下所有職缺一併轉為 off 職缺。
- 反之，公司由 off 轉為 on 時，職缺**不會**自動變回 on，需由客戶重新開啟。

**暫停徵才（off 公司）的特性**：

- 暫停期間不耗用刊期天數
- 有獨立的天數上限（通常 180 天，實際依合約而定）
- 暫停期間**完全禁止 BC 溝通**（包含進行中的對話），即 B 端企業與 C 端求職者之間的任何往來都不可進行。涵蓋行為包含但不限於：
  - 傳訊息
  - 邀約面試
  - 邀請到職
  - 發送感謝函
- 暫停期間**不允許搜尋、查看求職者履歷**；但**已儲存的履歷**仍可查看

**相關概念**：PO 單、刊期、預約刊登

## PO 單

**定義**：Product Order，即「產品訂單」，也就是客戶購買的一張**刊登合約**。系統與團隊內部一律以「PO 單」指稱單張刊登合約。

> ❗ 英文縮寫 PO 的全名現今已不可考——有人說是 **Purchase Order**，也有人說是 **Product Order**。

**PO 單的權利義務**：泛指一張 PO 單所載明的各項數值參數，包含但不限於：

- 刊登天數
- 暫停天數
- 刊登職務數 / 地區 / 職類
- 履歷接觸數
- 帳號數

**相關**：刊期、廣告刊登、接續單、未來單、多 PO 單

---

## 刊期

**定義**：客戶購買 PO 單後，該 PO 單所獲得的可刊登區間（例如 365 天）。

**重要規則**：

- 刊期內可刊登多個職缺，職缺上限數量依 PO 單而定。
- 刊期會被「暫停徵才」凍結——暫停期間**不會**耗用刊期天數。
- 暫停徵才有獨立的天數上限（**通常 180 天**，實際依 PO 單而定）。

**生命週期**：

1. 客戶購買 PO 單
2. 進入刊登狀態（或預約未來某時間才開始曝光）
3. 期間可由客戶自行暫停徵才（不耗用刊期）
4. 合約時間到 → 自動暫停

**相關**：PO 單、廣告刊登

## 預約刊登（內部黑話：未來單）

**定義**：客戶購買了 PO 單，但不立即開始曝光，而是預約未來某個日期才啟動。團隊內部稱這類 PO 單為「**未來單**」。

**判定條件**：購買的 PO 單**開始刊登日為未來日期**，即屬未來單。與購買當下廣告刊登狀態無關：

- 廣告刊登狀態為 ON 時，客戶購買非當天開啟的 PO 單 → 未來單
- 廣告刊登狀態為 OFF 時，客戶購買非當天開啟的 PO 單 → 未來單

**與接續單的差異**：未來單與前一張 PO 單之間**有空檔的天數**；接續單則無縫接上（見「接續單」條目）。

**相關**：PO 單、刊期、廣告刊登、接續單

---

## 接續單

**定義**：在當前 PO 單 A 仍在執行時，客戶購買的下一張 PO 單 B，其**開始刊登日剛好為 PO 單 A 結束日的隔天**。此情境下 PO 單 A 結束後，廣告刊登保持 **ON** 並直接啟用 PO 單 B，中間沒有空檔的天數——這張 PO 單 B 即稱為「接續單」。

**範例**：

> 正在執行的 PO 單 A 到期日為 2023/9/15，客戶購買的下一張 PO 單 B 開始刊登日為 2023/9/16，則 PO 單 B 即為接續單。

> 註：刊期以「天」為單位計算。

**與未來單的差異**：

| 類型   | 與前一張 PO 單的關係                 |
| ------ | ------------------------------------ |
| 接續單 | 緊接著前一張 PO 單結束後無縫接上     |
| 未來單 | 與前一張 PO 單之間有空檔的天數       |

**相關**：PO 單、刊期、廣告刊登、未來單、多 PO 單

---

## 多 PO 單

**定義**：「多 PO 單」是允許**一間公司同時持有多張 PO 單**的新商模。

**舊商模 vs. 新商模**：

| 商模       | 規則                                                                       |
| ---------- | -------------------------------------------------------------------------- |
| 舊商模     | 一間公司最多只能有一張 PO 單；後續購買的 PO 單會與現有 PO 單**合成為一張**  |
| 新商模（多 PO 單） | 允許一間公司持有多張 PO 單；可同時持有的 PO 單**上限可設定**         |

**重要說明**：

- 「允許多 PO 單」即表示客戶可同時擁有 **2 張以上**的 PO 單。
- 可同時持有的 PO 單數量有上限，該上限可由系統設定。
- 在多 PO 單商模下，後續購買的 PO 單不再合併，而是以接續單或未來單形式獨立存在。

**相關**：PO 單、刊期、接續單、未來單
